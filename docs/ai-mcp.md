# AI-агенты

> <img src="../resources/brand/cat-surprised.png" alt="" width="26" align="left"> Навыки объясняют агенту команды расширения, MCP даёт их вызвать.

Расширение помогает AI-агентам (Cursor, Claude, Copilot) работать с проектом 1С: агент узнаёт, какие команды есть, и выполняет их через [MCP-сервер](/mcp/) или файл-триггер.

![Навыки для AI и MCP](../walkthrough/images/step9.png)

## Навыки для агента

В дереве **1С: Инструменты** → раздел **Навыки для AI**:

- **Добавить навыки разработки 1С (cc-1c-skills)** — XML, формы, роли, СКД, метаданные; скачиваются с GitHub при каждом вызове.
- **Добавить навыки расширения (команды и MCP)** — инструкции по командам расширения и MCP по доменам.
- **Добавить навыки OneScript**, **Vanessa Automation**, **YAxUnit** и **xUnit** — скачиваются с GitHub при каждом вызове (репозитории `yellow-hammer/skills-onescript`, `skills-vanessa-automation`, `skills-yaxunit`, `skills-xunit`). Папка зависит от кнопки: Cursor (`.cursor/skills` и `.cursor/rules`), GitHub Copilot (`.github/skills` и `.github/instructions`), Claude Code (`.claude/skills` и `.claude/rules`). Команда «Добавить навыки YAxUnit» не ставит движок тестов: для движка есть «Добавить YAxUnit».

При установке выбирается папка назначения: `.cursor/skills/`, `.github/skills/`, `.claude/skills/` или другая, которую использует агент.

## Файл-триггер

Агент может создать файл `.cursor/1c-platform-tools-run-command` с одной строкой — идентификатором команды:

```txt
1c-platform-tools.run.designer
```

Расширение выполнит команду и удалит файл.

## MCP-сервер

Прямой вызов команд с результатом, счётчиками тестов и параметрами вызова даёт отдельное расширение **1C: Platform Tools MCP**. Установка, подключение к VS Code, Cursor и Claude Code, параметры инструментов и примеры фраз для агента собраны в разделе [MCP-сервер](/mcp/).

Данные базы агент читает через стандартный интерфейс OData, см. [Данные через OData](odata.md).

### С каким окном работает агент

Каждое окно VS Code или Cursor открывает свой канал для MCP-сервера и записывает в реестр окон, какие папки и проекты оно обслуживает. MCP-сервер находит в реестре окно, из которого запущен агент, и выполняет команды в нём. Порт, токен и включение канала настраивать не нужно, окна друг другу не мешают.

- Команды агента выполняются в [текущем проекте](projects.md#текущий-проект) окна, а с `projectPath` в указанном проекте этого окна. В окне из нескольких папок (`.code-workspace`) годится проект из любой папки окна, текущим без выбора остаётся проект из настройки `1c-platform-tools.project.default`.
- Проект другого окна окно агента не выполняет: приходит отказ `WORKSPACE_MISMATCH` с именем окна, в котором проект открыт.
- Агенту вне окон, например Claude Code в терминале, окно выбирается по `projectPath`. Проекта нет ни в одном окне — приходит `WINDOW_NOT_FOUND`: откройте проект в VS Code или Cursor.

Реестр лежит в домашнем каталоге пользователя (`~/.1c-platform-tools/windows`) на той машине, где работает хост расширений. В Remote, WSL и Codespaces это удалённая машина, и MCP-сервер должен работать там же: VS Code запускает его там сам. Канал окна — именованный канал Windows или Unix-сокет со случайным именем, запросы по нему выполняются только с токеном окна из реестра. На Linux и macOS каталоги сокета и реестра к тому же закрыты от других пользователей.

В недоверенной папке канал не открывается и окна нет в реестре: агент в ней команды не выполняет.

TCP-канал (`1c-platform-tools.ipc.enabled`, `ipc.port`, `ipc.token`) MCP-серверу не нужен: он для внешних программ, которые вызывают команды расширения по localhost.
